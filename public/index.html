Everything a finance analyst checks first

Six focused views, each backed by a real database query.

Financial KPIs

GTV, net transaction value, net fee revenue, refund rate, average transaction value and success rate, with the formula on every card.

Revenue trends

Daily, weekly or monthly trends with date, merchant and payment-method filters. Partial periods are marked so they don't look like a drop.

Transaction explorer

Search, filter and sort every payment, then open one to see its refunds and any anomaly flags.

Data validation

Missing values, invalid amounts and dates, duplicate IDs and inconsistent refunds are rejected at import, each with the row and reason.

Anomaly detection

Explainable rules flag possible double charges, bursts of failed attempts, unusually large payments and fast full refunds.

CSV import

Upload your own transactions, preview the validation result, then import. Re-imports never create duplicates.

How it works

Pandas cleans the data at import. SQL does the math on every request.

  1. 1

    Import

    Transaction and refund CSVs are read as text, so nothing is silently type-converted.

  2. 2

    Validate

    Pandas checks every row and records rejected rows with a code and a reason.

  3. 3

    Store

    Clean rows are bulk-loaded into PostgreSQL in one transaction, with keys that block duplicates.

  4. 4

    Analyse

    A FastAPI backend runs SQL aggregates, and the dashboard charts the results.

Metrics with exact definitions

Transaction volume, gross value and revenue are different numbers, and InsightFlow keeps them separate.
